\chapter{Conclusions \& Future Work}
\label{conclusions}

\section{Summary of Contributions}
\label{sec:summary-contributions}

\par This dissertation presented the MSA Detector, an automated static analysis tool for detecting architectural anti-patterns in Java-based microservice systems. The tool implements a multi-level analysis pipeline that combines intra-service code analysis, performed by integrating DesigniteJava as an external subprocess together with Spoon-based structural metrics, with inter-service dependency analysis based on Spoon's Abstract Syntax Tree traversal and graph algorithms. God Service detection, for example, evaluates six structural metrics including Tight Class Cohesion to identify classes that concentrate too many responsibilities, while Chatty Service detection combines dependency-graph edge analysis with source-based scanning for HTTP client patterns. Thus, the tool uses both code-level indicators and structural metrics as signals for architectural-level anti-patterns, bridging a gap that existing tools address only partially or not at all.

\par The detection pipeline covers ten anti-patterns organized across four architectural dimensions: service design (Nano Service, God Service), communication (Chatty Service, Cyclic Dependency, Hardcoded Endpoints, ESB Misuse), data management (Shared Database) and deployment and coupling (Distributed Monolith, API Versioning Absence, Wrong Cuts). Each detector is implemented as a pluggable Strategy component with configurable thresholds externalized in the application configuration. Every detected anti-pattern is accompanied by source code snippets extracted during analysis, affected service lists and remediation guidance, with the aim to aid developers in understanding and acting on the findings without additional manual inspection.

\par A further contribution is the automated microservice boundary detection mechanism, which identifies services by scanning for build files and filtering out non-service modules through an exclusion heuristic, eliminating the manual service enumeration that most existing tools require. The composite health score quantifies overall architectural quality on a 0-100 scale with letter grading and decomposes it into four weighted categories: anti-pattern severity, code quality, architectural coupling, and service sizing, each with an itemized list of deductions. A built-in analysis diff feature compares successive analysis runs, which teams can use to track architectural health trends over time and measure the concrete impact of refactoring efforts. The tool is delivered as a web application with a RESTful API, an Angular-based dashboard and Docker-based deployment, supporting both interactive use and programmatic integration into existing CI/CD pipelines.

\par The evaluation on eleven open-source microservice projects, encompassing 130 detected microservices and approximately 274\,000 lines of code, demonstrated that the MSA Detector can identify architectural anti-patterns that are confirmed by manual inspection. A total of 126 anti-pattern instances were detected across nine distinct types, including ESB Misuse, Chatty Service, Cyclic Dependency and Wrong Cuts, validating detectors that target inter-service communication topology and cross-boundary coupling.

\section{Limitations}
\label{sec:limitations}

\par Several limitations of the approach should be acknowledged. The detection pipeline is restricted to Java-based microservice systems and is optimised for Spring Boot conventions; while it also accommodates other JVM frameworks such as Jakarta EE/CDI, detection coverage is highest for Spring-based projects, and services written in other languages cannot be analyzed. The tool relies exclusively on static analysis and does not incorporate runtime data from distributed tracing or actual call frequency measurements, meaning that anti-patterns which manifest only at runtime may not be detected accurately. The automated microservice detection heuristic, while effective for multi-module Maven and Gradle projects, may produce false positives for non-service submodules such as shared libraries, and may miss services that do not follow conventional directory structures. Similarly, the inter-service dependency resolution cannot handle dynamically constructed URLs resolved through external configuration services such as Spring Cloud Config, potentially leaving some dependencies undetected.

\par The composite health score uses a linear deduction formula with fixed penalty weights that have not been empirically validated across a large corpus of projects, and the default detection thresholds were chosen based on values reported in the literature and reasonable engineering judgement rather than systematic calibration. Finally, the evaluation was conducted on eleven open-source projects of varying size and maturity, which may not be fully representative of enterprise microservice systems in terms of scale, complexity and the distribution of anti-patterns encountered in production environments.

\section{Future Work}
\label{sec:future-work}

\par Several directions for future research and development emerge from this work. The most impactful extension would be multi-language support, enabling the analysis of microservices written in Python, Go, .NET or Node.js. A language-agnostic dependency graph could be constructed from infrastructure artifacts such as Docker Compose files, Kubernetes manifests or API gateway configurations, while language-specific analyzers would handle intra-service code smell detection for each supported ecosystem.

\par The anti-pattern catalog could be extended with additional patterns not yet covered, such as timeout misconfiguration in inter-service calls and the absence of an API gateway. Machine learning-based detection represents a longer-term direction: training classifiers on labeled datasets of microservice projects, or applying graph neural networks to the dependency graph could capture subtle anti-pattern manifestations that rule-based detectors miss, though the scarcity of labeled training data for microservice anti-patterns remains a significant challenge.

\section{Concluding Remarks}
\label{sec:concluding-remarks}

\par As microservices adoption continues to grow, the need for automated architectural quality assurance becomes increasingly pressing. Manual architectural reviews do not scale to systems with dozens or hundreds of services and thousands of inter-service dependencies, yet the consequences of undetected anti-patterns (e.g. cascading failures, deployment friction, mounting maintenance costs) can be severe. This dissertation has demonstrated that a static analysis tool combining code-level smell detection with architectural-level dependency analysis can provide meaningful, actionable feedback on microservice architectural quality without requiring a running system or manual configuration of service boundaries.
